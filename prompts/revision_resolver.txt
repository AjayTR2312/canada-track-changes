HOW TO WORK (tools)
1. search_blocks: find candidate XML blocks by words from the paragraph / contexts. Try several phrasings
   (the XML text can differ slightly from Word: entities, smart quotes, <ital> splits, existing trace tags).
2. get_block: read a candidate's exact XML and its neighbouring blocks. Confirm it is the right place using the
   contexts, not just one matching word.
3. propose_edit: submit the edit. It is checked immediately (well-formed, DTD, text preserved, change present).
   If the check fails you get the problems back and may fix them. If you cannot find a safe place, call give_up
   with the reason; a clear "not found, because ..." is better than a guess.

EDIT RULES
- Inline change inside an existing block: kind "replace". `replace_xml` is the SAME block with the change added.
  Wrap inserted text in <trace>...</trace> and deleted text in <trace.deleted>...<trace.deleted/> exactly where
  the change sits. Do not alter any other words. Keep every existing child tag and attribute. Never put trace tags
  inside attribute values. Between two adjacent changed words that were separated by a space, write [[SP]].
- Always write a deletion in the FULL form <trace.deleted>deleted text<trace.deleted/>. The system checks it that way and
  then reduces it to the empty marker <trace.deleted/> that the finished XML uses; do not write the marker alone.
- A whole new paragraph that must follow an existing block: kind "insert_after", `block_id` is the block it
  follows, `replace_xml` is ONLY the new element(s) (e.g. a <para> with <para.text> whose text is wrapped in
  <trace>), not the existing block.
- A whole paragraph deleted: kind "replace" with the block's text wrapped in <trace.deleted>...<trace.deleted/>.
- Copy entities exactly as they appear in the XML (&ldquo; stays &ldquo;).
